Open this doc See its model

  1. It reads your source.

    Markdown, text, HTML, a URL or a PDF becomes an outline with section ids.

  2. It drafts the model, look and timeline.

    A draft picks a theme and an accent that clears contrast, and marks the sentences to highlight. Edit the JSON if you disagree.

  3. The engine renders one HTML file.

    Inline CSS and SVG, no network assets. Print, reduced motion and no script all show the final state.

  4. Cues play in step with the sentences.

    Highlight a sentence and its figure lights up. Numbers count and text types, always inside their own box.

  5. One model, three themes.

    Switch the stage and the whole page follows.

The same timeline, as a clip

MP4
For sharing. 2.5 to 3.7 MB for 20 seconds in our samples.
GIF
For READMEs, 720 pixels wide. About 12 MB for 20 seconds.
WebM
For the web, from the same frames.

Frames come from headless Chromium and ffmpeg, both optional. Two renders on one machine match frame for frame.

Three commands to a clip

living-docs-axi ingest notes.md --draft -o notes.json
living-docs-axi render notes.json -o notes.html
living-docs-axi render notes.json --format mp4 -o notes.mp4

Run them through npx -y -p @bytesbybrandon/living-docs. Video also needs playwright and ffmpeg; the timeline guide has the exact call.

What you can rely on

  • One file per document

    No CDN, web fonts or remote images.

  • Deterministic output

    Same model and theme, same bytes.

  • Escaped by default

    Only http, https, mailto, hash and relative links survive.

  • Print ready

    Figures, tables and callouts stay unbroken.
