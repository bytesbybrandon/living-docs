From source to page

Ingest keeps large sources bounded, a draft model renders immediately, and an author upgrades it against the schema.

  1. Ingest

    Markdown, text, HTML, URL, or PDF becomes an outline with section ids and word counts.

  2. Plan

    Pick a theme and curated style tokens: palette or seed color, type pairing, density, figure treatment.

  3. Author

    Write the model: prose, tables, algorithms, diagrams, charts, callouts. Strict validation points at the exact path.

  4. Render

    One HTML file with inline CSS and SVG. Print rules for papers, optional figure motion, no network assets.

living-docs-axi ingest notes.md --draft --theme paper-dark -o docs/notes.model.json
living-docs-axi validate docs/notes.model.json
living-docs-axi render docs/notes.model.json --theme paper-dark -o docs/notes.html
living-docs-axi preview docs

Built for agents

The CLI follows the AXI principles: compact output, a content-first home view, and next-step hints. The same core is an MCP server over stdio.

MCP server

Add it to any MCP client.

{
  "mcpServers": {
    "living-docs": {
      "command": "npx",
      "args": ["-y", "-p", "@bytesbybrandon/living-docs", "living-docs-mcp"]
    }
  }
}

What you can rely on

These are properties of the engine, each covered by tests.

One file per document

CSS, SVG, and the console runtime are inlined. No CDN, web fonts, or remote images.

Deterministic output

The same model and theme produce the same bytes, including SVG ids, graph layout, and derived palettes.

Escaped by default

Document text is HTML escaped. Only http, https, mailto, hash, and relative links survive.

Curated styling

Style tokens are an allowlist. Seed colors are corrected until the accent clears contrast. No arbitrary CSS.

Motion that respects you

Figure motion freezes for print and under reduced-motion preferences, and content stays visible while it runs.

Print ready

Paper themes keep figures, tables, algorithms, and callouts unbroken across pages.
